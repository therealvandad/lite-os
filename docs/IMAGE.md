# What is inside a Lite OS image

> Generated from `image/*.json` and `image/layout/*` by `tests/Export-TweakDocs.ps1` - do not edit this file by hand.
> Change the JSON / XML, then run `powershell -NoProfile -ExecutionPolicy Bypass -File tests\Export-TweakDocs.ps1`.

The **Lite OS Builder** (`LiteOS-Builder.cmd`) downloads the official Windows 11 ISO from Microsoft on **your** PC
(or uses an ISO you picked), removes the components below from the image, bakes in the tweaks from
[TWEAKS.md](TWEAKS.md), the branding, the Start / taskbar layout and the installers listed here, and writes
`LiteOS.iso`. Nothing is patched: Windows binaries, `ProductName` and `EditionID` stay Microsoft's, so
activation works with your own license. Lite OS never hosts or uploads a Windows image.

## Lite vs Core

| | **Lite** (default) | **Core** (opt-in, X-Lite style) |
|---|---|---|
| Tweaks | Balanced | Extreme |
| Removed from the image | 3 Lite default(s) | the Lite ones plus 4 Core default(s) |
| Windows Update / Microsoft Store | Keep working (monthly security updates) | **Not serviceable**: to update, rebuild from a newer official ISO |
| Windows Defender | On | Removed / disabled - use another antivirus or accept the risk |
| Microsoft Edge | Kept | Browser removed (WebView2 and its updater kept, launchers still work) |
| WinRE (recovery) | Kept | Disabled after Setup - no "Reset this PC" or startup repair |
| Xbox app, Game Pass, Gaming Services | Work | Installed, but Store and Game Pass installs / updates need the Windows Update service and fail |
| Kernel anti-cheat | Works | Usually works; games that require Defender, VBS or recent updates may refuse to start |

Every image is cleaned with `DISM /Cleanup-Image /StartComponentCleanup /ResetBase` (both modes): installed
updates can no longer be uninstalled, but new updates install normally in Lite.

Override single entries with `-Include` / `-Exclude <id>` (exact ids or wildcards, Exclude wins) or in the
Builder's **Customize** list. Entries whose default is **no** are only removed when you pick them.

<a id="core-removals"></a>

## Removed in Core only

> **Core only.** These break Windows Update servicing, Defender or recovery on purpose. Read every description.

| ID | Name | Default | Risk | Removes | Description |
|---|---|---|---|---|---|
| `image.defender` | Microsoft Defender (Core: disabled) | yes | high | custom offline script; provisioned apps `Microsoft.SecHealthUI` | CORE ONLY, NOT SERVICEABLE. Disables Microsoft Defender at the image level: sets the Defender services (WinDefend, WdNisSvc, WdNisDrv, WdFilter, WdBoot, Sense, MDCoreSvc) to Start=4 (disabled) in the offline SYSTEM hive, turns SmartScreen off via policy, hides the Windows Security notifications, the Virus & threat protection area and its Settings page, removes the SecurityHealth tray entry and the Windows Security (SecHealthUI) app from the image, and disables SecurityHealthService during SetupComplete (only SYSTEM may change that service). Removing SecHealthUI is a deliberate Core-only override of the Lite protected-app list. Downside: THE PC HAS NO REAL-TIME ANTIVIRUS OR SMARTSCREEN. Only use Core on a machine where you install and maintain your own security, and understand that re-enabling Defender cleanly usually means rebuilding from a newer ISO. WdBoot/WdFilter are boot/early-launch drivers, so disabling them offline can also affect early-boot protection. |
| `image.windows-update` | Windows Update stack (Core: disabled) | yes | high | custom offline script; leaves out tweaks `updates.no-auto-restart`, `updates.notify-only` | CORE ONLY, NOT SERVICEABLE. Disables the Windows Update servicing stack: sets wuauserv, UsoSvc and WaaSMedicSvc to Start=4 (disabled) in the offline SYSTEM hive and writes the NoAutoUpdate / DoNotConnectToWindowsUpdateInternetLocations policies; SetupComplete checks the same state again on the installed system. The update tweaks that would write NoAutoUpdate=0 (updates.no-auto-restart, updates.notify-only) are left out of the image. Downside: THE PC WILL NO LONGER RECEIVE SECURITY OR FEATURE UPDATES. This is the X-Lite style 'frozen' build; to update you rebuild from a newer official ISO. Microsoft Store and Xbox / Game Pass app installs and updates need the Windows Update service and fail while it is disabled (error 0x80070422), so Core is for a locked-down, offline-style gaming box only. |
| `image.edge` | Microsoft Edge browser (Core) | yes | medium | Microsoft Edge browser (WebView2 and Edge Update are kept) | CORE ONLY. Removes the Microsoft Edge browser from the image: deletes Program Files (x86)\Microsoft\Edge and \EdgeCore, the Edge Start Menu and public Desktop shortcuts, the Edge uninstall entry and the browser's Edge Update registration, disables the browser's elevation service, and sets the Edge Update install policy so Edge is not reinstalled (InstallDefault=0 and Edge Stable blocked, the WebView2 Runtime explicitly allowed). The Edge WebView2 Runtime, the EdgeWebView folder and Edge Update are NEVER removed, so apps that embed WebView2 (Xbox app, Game Pass, many launchers) keep working and WebView2 keeps receiving its security updates. Downside: there is no bundled browser, so the first thing to do on the new PC is install one (with winget or from another PC); the Edge Update install policy is formally documented for managed devices, so a later Edge installer you run yourself can still bring Edge back. |
| `image.winre` | Windows Recovery Environment (Core) | yes | medium | Windows Recovery Environment (WinRE), disabled after Setup | CORE ONLY. Disables the Windows Recovery Environment after Setup: Winre.wim stays in the image because Windows 11 24H2 / 25H2 Setup fails without it, then SetupComplete runs 'reagentc /disable' and deletes C:\Windows\System32\Recovery\Winre.wim (partitions are never touched; the empty recovery partition stays). Downside: the boot-time 'Advanced startup' / recovery options (Reset this PC, Startup Repair, offline troubleshooting) are gone; you recover with external install media instead. Saves a few hundred MB. Does not affect normal boot, System Restore points, or your files. |
| `image.speech` | Speech recognition / text-to-speech (Core) | no | medium | capabilities `Language.Speech*`, `Language.TextToSpeech*` | CORE ONLY, OFF BY DEFAULT. Removes the Speech and Text-to-Speech language capabilities. Downside: Windows voice typing, the Narrator's higher-quality voices, in-game voice commands and any app that uses Windows speech recognition or TTS stop working, and they are hard to add back offline. Left off by default because many games and accessibility tools rely on them; only include it if you are sure you do not use speech. |
| `image.handwriting` | Handwriting recognition (Core) | no | medium | capabilities `Language.Handwriting*` | CORE ONLY, OFF BY DEFAULT. Removes the Handwriting language capability used by pen and touch input. Downside: writing with a pen in input fields and handwriting-to-text stop working; normal typing and the touch keyboard are unaffected. Left off by default because pen/touch devices need it; only include it on a keyboard-and-mouse-only build. |

<a id="installers"></a>

## Preinstalled software

Source: `image/installers.json`. The **builder** downloads each installer from the official URL on your PC,
refuses it unless its Authenticode signature is valid and the signer contains the publisher shown, and copies it
to `C:\LiteOS\installers` in the image. `SetupComplete` runs them silently, in this order, before the first sign-in.
Lite OS ships none of these files itself. Pick them in the Builder or with `-Installers default|none|<ids>`.

| ID | Name | Mode | Default | Silent install | Signed by | Official source |
|---|---|---|---|---|---|---|
| `vcredist-x64` | Visual C++ 2015-2022 Redistributable (x64) | both | yes | `vc_redist.x64.exe /install /quiet /norestart` | Microsoft Corporation | [aka.ms](https://aka.ms/vs/17/release/vc_redist.x64.exe) |
| `vcredist-x86` | Visual C++ 2015-2022 Redistributable (x86) | both | yes | `vc_redist.x86.exe /install /quiet /norestart` | Microsoft Corporation | [aka.ms](https://aka.ms/vs/17/release/vc_redist.x86.exe) |
| `directx-jun2010` | DirectX End-User Runtimes (June 2010) | both | yes | `directx_Jun2010_redist.exe /Q /T:{extractDir}` then `DXSETUP.exe /silent` | Microsoft Corporation | [download.microsoft.com](https://download.microsoft.com/download/8/4/A/84A35BF1-DAFE-4AE8-82AF-AD2AE20B6B14/directx_Jun2010_redist.exe) |
| `dotnet-desktop-8` | .NET Desktop Runtime 8 (x64) | both | yes | `windowsdesktop-runtime-8-win-x64.exe /install /quiet /norestart` | Microsoft Corporation | [aka.ms](https://aka.ms/dotnet/8.0/windowsdesktop-runtime-win-x64.exe) |
| `steam` | Steam | both | yes | `SteamSetup.exe /S` | Valve | [cdn.fastly.steamstatic.com](https://cdn.fastly.steamstatic.com/client/installer/SteamSetup.exe) |

Installer fields: `url` (official https download), `file` (saved as), `args` (silent switches), `publisher`
(must be part of the Authenticode signer subject), `mode` (`lite`, `core` or `both`), `default`, and optional
`description`, `successCodes` (exit codes that count as success; default 0, 1638, 3010, 1641 - 3010 / 1641 mean
success with a reboot pending, 1638 that a newer version is already installed), `timeoutMinutes` (default 15)
and `extract` for self-extracting packages: `args` then contains `{extractDir}` (the runner replaces it with
`C:\LiteOS\installers\_extract\<id>`, a path without spaces), and after the extraction the runner starts
`extract.run` from that folder with `extract.args`. `{temp}` is a synonym of `{extractDir}`, `{dir}` is the
installers folder.

## Branding

Source: `image/branding.json`. `<mode>` is Lite or Core, `<build>` the Windows build of your ISO.

| Where it shows | Value |
|---|---|
| Settings > System > About > Support (manufacturer) | Lite OS |
| OEM model | Lite OS &lt;mode&gt; (&lt;build&gt;) |
| Support link | https://github.com/therealvandad/lite-os |
| Registered organization | Lite OS |
| Boot menu entry | Lite OS |
| Windows Setup image name | Lite OS &lt;mode&gt; |
| ISO volume label | `LITEOS_...` |

Lite OS does not patch Microsoft binaries (`basebrd.dll`, `winver`) and does not change `ProductName` or
`EditionID`: Windows Update and activation must keep recognising your edition.

## Start menu and taskbar

Start pins (`image/layout/LayoutModification.json` in the documented OEM format, copied to the Default
profile and applied for every new account - you can rearrange them afterwards). File Explorer, Microsoft Store
and Edge (Lite) are pinned on page 1 by Windows itself (an OEM pin of an app Windows already pins there is
ignored); the OEM pins add:

1. Steam (preinstalled) - `%ALLUSERSPROFILE%\Microsoft\Windows\Start Menu\Programs\Steam\Steam.lnk` (page 1)
2. Xbox - `Microsoft.GamingApp_8wekyb3d8bbwe!Microsoft.Xbox.App` (page 1)
3. Terminal - `Microsoft.WindowsTerminal_8wekyb3d8bbwe!App` (page 1)
4. Settings - `windows.immersivecontrolpanel_cw5n1h2txyewy!microsoft.windows.immersivecontrolpanel` (page 1)

Taskbar pins (`image/layout/TaskbarLayoutModification.xml`, `PinListPlacement="Replace"`, referenced by
`LayoutXMLPath` in the image; applied at first sign-in, you can unpin anything):

1. File Explorer - `Microsoft.Windows.Explorer`
2. Microsoft Edge (Lite only; not installed in Core) - `MSEdge`
3. Steam (preinstalled) - `%ALLUSERSPROFILE%\Microsoft\Windows\Start Menu\Programs\Steam\Steam.lnk`
4. Xbox - `Microsoft.GamingApp_8wekyb3d8bbwe!Microsoft.Xbox.App`
5. Microsoft Store - `Microsoft.WindowsStore_8wekyb3d8bbwe!App`

Pins for apps that are not installed (for example Edge in Core) simply do not appear.
