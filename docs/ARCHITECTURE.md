# Lite OS — architecture contract

Lite OS is a **gaming-focused customization of Windows 11** (24H2 / 25H2+, build >= 26100).
It is distributed as **scripts only**. We never ship a modified Windows image, Windows binaries,
license keys or activators. Users bring their own official ISO from microsoft.com and their own license.

Two ways to use it, sharing one tweak engine and one tweak catalog:

1. **Playbook** – `Start-LiteOS.cmd` / `LiteOS.ps1` applies tweaks to the running Windows install.
2. **ISO builder** – `builder/Build-LiteOS.ps1` turns an official Windows 11 ISO into a Lite OS ISO.
   The ISO's first logon runs the playbook non-interactively at the level chosen at build time.

## Hard rules (all files)

- **Windows PowerShell 5.1 compatible.** No PS7-only syntax: no `??`, `?.`, ternary `a ? b : c`,
  `&&`/`||` pipeline chains, `-Parallel`, `ConvertFrom-Json -AsHashtable`, `Join-Path` with >2 child args,
  `Get-Content -AsByteStream`. `ConvertFrom-Json` returns PSCustomObject.
- **ASCII only** in `.ps1/.psm1/.psd1/.cmd` (PS 5.1 reads BOM-less files as ANSI). No smart quotes, no emoji.
- `Set-StrictMode -Version 2.0` and `$ErrorActionPreference = 'Stop'` in entry scripts; catch per action so
  one failed tweak never aborts the whole run.
- Everything that changes the system must be **recorded for revert** (see Backup) and **logged**.
- Never wipe disks, never touch partitions, never disable Secure Boot/TPM in firmware.
- **Balanced** level must keep working: Windows Defender, Windows Update security updates, Microsoft Store,
  Xbox app / Game Pass / Gaming Services, Game Bar, Edge + WebView2, Windows Hello, VBS/HVCI state,
  TPM, BitLocker if the user enables it, and kernel anti-cheat (Vanguard, EAC, BattlEye, Ricochet,
  FACEIT, EA Javelin). Anything that endangers these is **extreme** only.
- Paths: install root on disk is `C:\LiteOS` (playbook payload), state is `$env:ProgramData\LiteOS`
  (`logs\`, `backup\`, `config.json`, `prev-*.txt` script state). Both must be writable by SYSTEM and
  Administrators only (protected ACL: SYSTEM + Administrators full control, Users read, owner Administrators),
  because backups hold undo scripts and registry data that run elevated. The builder sets this ACL in the
  image; `Initialize-LiteOS` (not in dry runs) sets it on the state folder of a running system.

## Tweak catalog schema (`tweaks/<category>.json`)

```json
{
  "category": "privacy",
  "title": "Privacy & telemetry",
  "tweaks": [
    {
      "id": "privacy.telemetry-off",
      "name": "Disable telemetry",
      "description": "One or two plain-English sentences for the user.",
      "level": "balanced",
      "default": true,
      "risk": "low",
      "reboot": false,
      "minBuild": 22000,
      "actions": [ ... ]
    }
  ]
}
```

- `id`: `<category>.<kebab-name>`, unique across all files.
- `level`: `balanced` | `extreme`. Level **Balanced** = balanced tweaks with `default:true`.
  Level **Extreme** = Balanced + extreme tweaks with `default:true`. `default:false` tweaks are only applied
  when explicitly included (`-Include` or Custom mode).
- `risk`: `none` | `low` | `medium` | `high`. Every `extreme` tweak must explain its downside in `description`.
- `reboot`: true if it needs a restart to take effect. `minBuild`/`maxBuild` (optional): skip outside range.

Category files: `privacy.json`, `ui.json` (ads, Copilot/Recall, start/search/taskbar/explorer),
`gaming.json`, `performance.json` (power, memory, scheduling), `network.json`, `services.json`,
`updates.json`, `security-extreme.json` (all `extreme`).

### Action types

| type | fields | revert record |
|---|---|---|
| `registry` | `path` (`HKLM:\...` or `HKCU:\...`), `name` (`""` = the key's default value; the engine also maps `(default)` / `@` to `""`), `kind` (`DWord`,`QWord`,`String`,`ExpandString`,`MultiString`,`Binary`), `value` (number / string / string[] / hex string for Binary) | previous existence, kind, value; created keys |
| `registry-delete` | `path`, optional `name` (omit = delete whole key) | exported previous values/key |
| `service` | `name`, `startup` (`Disabled`,`Manual`,`Automatic`,`AutomaticDelayed`), optional `stop` (bool) | previous start type + DelayedAutostart + status (also recorded when only a stop was needed, so revert restarts it) |
| `task` | `path` (e.g. `\Microsoft\Windows\Application Experience\`), `name`, `state` (`Disabled`/`Enabled`) | previous state |
| `powershell` | `script` (string), optional `undo` (string), optional `perUser` (bool) | the `undo` string + hive tag |
| `appx-remove` | `packages` (array of package family-name prefixes, wildcard allowed) | list removed (not auto-restorable; revert prints winget/Store hint) |

`HKCU:` actions are applied to the **current user AND the Default user profile**
(`C:\Users\Default\NTUSER.DAT`, loaded via `reg load HKU\LiteOS_Default`, always unloaded in `finally`
after `[gc]::Collect()`), so new accounts get them too. Exception: `HKCU:\Software\Classes\...` lives in
`UsrClass.dat`, not `NTUSER.DAT`, so those actions are applied to the current user only.
Missing services/tasks are logged as `skipped`, not errors.

`powershell` actions run once, in the elevated user's context, unless `"perUser": true`: then they run once
per user hive like `HKCU:` actions (hive `User`, then `Default` when the Default profile is loaded). Before
the script runs the engine defines two string variables:

- `$LiteOSUserRoot` - registry root to use instead of `HKCU:` (`HKCU:`, `Registry::HKEY_USERS\LiteOS_Default`,
  or `Registry::HKEY_USERS\<SID>` when another admin reverts a backup and that user's hive is loaded).
- `$LiteOSHiveTag` - file-name-safe tag (user SID or `Default`) for per-hive state files in
  `$env:ProgramData\LiteOS` (e.g. `prev-dx-SwapEffectUpgradeEnable-<tag>.txt`).

Scripts must never hard-code `HKCU:\` (tests enforce this). Script output convention: a line starting with
`SKIPPED:` (not applicable on this PC, e.g. a laptop) or `UNCHANGED:` (already in the wanted state) means the
script changed **nothing**; the engine reports `skipped` / `unchanged` instead of `applied` and drops the
write-ahead backup entry, so reverting that run never undoes an earlier run's change. Scripts keep their own
previous value in a state file written only if it does not exist yet; an `undo` must be a **no-op when its state
file is missing** (that revert already ran, or nothing was changed), so reverting several backups in a row
always ends in the original state.

## Engine API (`src/LiteOS.Engine.psm1`)

```
Initialize-LiteOS            -> creates ProgramData dirs, starts log, returns context object
Get-LiteOSCatalog [-Path]    -> array of tweak objects (with .category added), validates schema, throws on dup ids
Select-LiteOSTweaks -Catalog -Level Balanced|Extreme|None [-Include ids] [-Exclude ids] [-Build n]
Invoke-LiteOSTweak  -Tweak -Context [-WhatIf]      -> result object {id, status: applied|skipped|failed, message}
Invoke-LiteOSPlan   -Tweaks -Context [-WhatIf]     -> runs all, writes backup json, returns results
New-LiteOSRestorePoint                              -> enables System Restore on system drive if needed, creates point
Get-LiteOSBackups / Restore-LiteOSBackup -Path      -> reverse-order revert
Write-LiteOSLog -Message [-Level Info|Warn|Error]
Test-LiteOSAdmin
```

`-WhatIf` must never change anything (used by tests and by `LiteOS.ps1 -DryRun`). `Initialize-LiteOS -DryRun`
only creates the state folders and writes its own log: no log rotation, no ACL change.

Backup file: `$env:ProgramData\LiteOS\backup\backup-<yyyyMMdd-HHmmss>.json` =
`{ version, created, level, build, entries: [ {tweakId, action, before, hive:'User'|'Default'|'Machine'} ] }`.
After a restore the file gets `restoreAttempted` and `restoreSummary`; `restored` is set only when no entry
failed, so a partly failed revert stays pending and is retried (every restore step is idempotent).
`Get-LiteOSBackups` marks backups not owned by SYSTEM, Administrators or the current elevated user as invalid,
and `Restore-LiteOSBackup` refuses them (they could have been planted by a standard account).

## Playbook entry (`LiteOS.ps1`)

Params: `-Level Balanced|Extreme`, `-Include`, `-Exclude`, `-Silent` (no prompts), `-DryRun`,
`-SkipRestorePoint`, `-SkipApps`, `-Apps <ids|default>`, `-FirstLogon` (used by the ISO; implies -Silent,
reads `$env:ProgramData\LiteOS\config.json` written by the builder, then reboots once at the end).

TUI menu: 1 Balanced (recommended) · 2 Extreme (shows the full warning list, requires typing `EXTREME`) ·
3 Custom (pick per category / per tweak) · 4 Install gaming apps · 5 Revert · 6 View log · 0 Exit.
Shows Windows build, and warns if build < 26100. Prints a summary table at the end.

## ISO builder (`builder/Build-LiteOS.ps1`)

Params: `-IsoPath` (official Windows 11 ISO, required), `-OutputPath` (default `.\LiteOS-<build>.iso`),
`-Edition` (name, default `Windows 11 Pro`; interactive pick if not found), `-Level Balanced|Extreme`,
`-Apps default|none|<ids>`, `-NoBypassRequirements`, `-KeepAutoEncryption`, `-WorkDir`.

Steps: admin + free-space check (>= 25 GB) -> mount ISO, copy to work dir, dismount -> detect
`install.wim`/`install.esd` -> export only the chosen edition to a new `install.wim` -> mount ->
offline `Remove-AppxProvisionedPackage -Path` from `apps-remove.json` -> offline registry
(load SOFTWARE / SYSTEM / Default NTUSER.DAT under `HKLM\LITE_*`, always unload): OOBE `BypassNRO`,
disable consumer-feature auto-installs and ContentDeliveryManager sponsored apps in the Default hive,
`PreventDeviceEncryption` unless `-KeepAutoEncryption`, LabConfig/MoSetup requirement bypass unless
`-NoBypassRequirements` -> copy payload (`LiteOS.ps1`, `Revert-LiteOS.ps1`, `Start-LiteOS.cmd`, `src\`, `tweaks\`)
to `<mount>\LiteOS` and write `<mount>\ProgramData\LiteOS\config.json` (plus `build-info.json` and a copy of the
build log with local paths replaced by placeholders) -> protected ACL on both folders (`icacls` with well-known
SIDs: owner Administrators, SYSTEM + Administrators full, Users read) -> dismount /commit ->
`boot.wim` index 2: LabConfig bypass -> export install.wim with max compression -> write
`autounattend.xml` to ISO root -> `New-IsoFile.ps1` -> print SHA256. Every mount/hive is cleaned up in
`finally` (also `dism /Cleanup-Wim` hint on failure).

Offline app removal uses the same id rules as the engine (`-Include` / `-Exclude` accept exact ids and
wildcards, Exclude wins) and refuses the engine's protected list (`Get-LiteOSProtectedApps`: built-in list +
`protected` from `apps-remove.json`); the builder imports the engine module for that.

`autounattend.xml` must **never** contain `DiskConfiguration` / partition wiping: the user picks the
disk in Setup (dual-boot safe). It never contains a product key, accounts, passwords or AutoLogon. The only
`ProductKey` element allowed is `<ProductKey><Key /></ProductKey>` with an **empty** Key in windowsPE
`Microsoft-Windows-Setup/UserData` (Setup refuses an answer file without it); the builder and the tests reject
anything else. It sets: requirement bypass in windowsPE (RunSynchronous `reg add` LabConfig),
`BypassNRO` in specialize, OOBE `HideOnlineAccountScreens`/`HideEULAPage`/`ProtectYourPC=3`
(local account created by the user in OOBE), and `FirstLogonCommands` running
`powershell.exe -NoProfile -ExecutionPolicy Bypass -File C:\LiteOS\LiteOS.ps1 -FirstLogon`.

## App lists

`tweaks/apps-remove.json`:

```json
{
  "title": "Remove preinstalled apps",
  "packages": [
    { "match": "Microsoft.BingNews", "name": "Microsoft News", "level": "balanced", "default": true }
  ],
  "protected": [ "Microsoft.WindowsStore", "Microsoft.DesktopAppInstaller", "Microsoft.GamingApp", "..." ]
}
```

- `match` = AppX package *Name* (wildcards allowed), matched against `Get-AppxPackage -AllUsers` / provisioned
  `DisplayName`. The engine turns each entry into a synthetic tweak `apps.remove.<match-lowercased>`
  (category `apps`, action `appx-remove`) so it is selectable like any other tweak.
- The engine and builder must **refuse** to remove anything matching `protected` (Store, winget/App Installer,
  Xbox app, Game Bar, Xbox Identity/TCUI/Speech overlay, Gaming Services, VCLibs, UI.Xaml, .NET Native,
  WindowsAppRuntime, Calculator, Photos, Notepad, Terminal, Paint, Snipping Tool, Security (SecHealthUI),
  Edge/WebView2, ShellExperienceHost, StartMenuExperienceHost, Widgets platform runtime).
- Removal = `Remove-AppxPackage -AllUsers` + `Remove-AppxProvisionedPackage -Online` (playbook), or
  `Remove-AppxProvisionedPackage -Path <mount>` (builder).

`tweaks/apps-install.json`:

```json
{ "apps": [ { "id": "Valve.Steam", "name": "Steam", "group": "Launchers", "default": true } ] }
```

`id` = exact winget package id (source `winget`). `src/Install-Apps.ps1 -Apps default|all|<ids> [-Silent]`
installs with `winget install --id <id> -e --source winget --accept-package-agreements
--accept-source-agreements --silent`, skips already-installed ids, never aborts on one failure.

## Safety for contributors and CI

- Importing `LiteOS.Engine.psm1` must have **no side effects** (no registry/log writes at import time).
- Tests are static/pure: schema validation, unique ids, level rules, ASCII-only, script parse, unattend
  safety (no `DiskConfiguration`), and `Select-LiteOSTweaks` logic. Tests must never apply tweaks.
